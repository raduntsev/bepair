# Впаре / Bepair

Общее пространство дня для пары. Сначала отмечаешь свой день — потом открывается день партнёра. Next.js 16 (App Router) + React 19 + Tailwind 4 + Supabase, устанавливается на телефон как PWA.

## Что внутри

| Раздел | Что умеет |
|---|---|
| **День** | Настроение цветом (единственное обязательное), заметка, день партнёра под замком до вашей отметки, «Вас попросили» — чек-лист, «Сделал для вас» — подтверждение, дни вместе и серия, день цикла (если включён), время партнёра (если «на расстоянии») |
| **Календарь** | Кольцо — ваш день, заливка — день партнёра, «оба» не режет ячейку; переход в любой прошлый день |
| **Летопись** | Лента всего посланного: весточки, снимки, голос, треки, письма |
| **Весточка** | Мгновенное сообщение партнёру со снимком, ссылкой на трек или голосовым |
| **Задачи** | Просьбы с весом-баллами, редактирование до выполнения, своя подборка шаблонов, статус «партнёр ещё не видел» |
| **Письма** | Вложения (фото, видео, аудио, голос), черновики, отложенная отправка с отменой, «открыть после того, как партнёр отметит день» |
| **Услуги** | Предложить услугу, попросить за баллы, «сделано, предложить снова» |
| **Курсы** | Курсы по психологии, которые проходят по шагам: урок открывается после предыдущего. Видно, на каком шаге партнёр. Ответы скрыты от партнёра, пока вы сами не откроете их — все сразу, одним переключателем. Напоминания в выбранные дни и время, уведомление о шагах партнёра. Первый курс — «Кто я и чего хочу?» (7 модулей, 37 шагов) |
| **Награды за курс** | Шаг +2 балла, модуль +10 и значок, весь курс +30 — в общий баланс, тратятся на услуги партнёра. Серия дней с курсом. Перед вопросами урока — теория, «Шаг пройден» проверяет, что все обязательные вопросы заполнены |
| **Журнал** | Журнал саморефлексии: свободные записи, дневник мыслей (ситуация → мысль → эмоция → реакция) и все ответы курсов по урокам. Журнал партнёра — под тем же переключателем, что и его ответы |
| **Где мы** | Вы и партнёр на карте. Каждый включает сам, но точку партнёра видно, только пока делитесь и вы. Раз в 5 минут, хранится одна последняя точка — без истории. На Android есть виджет «Карта» |
| **Ещё** | Уведомления, профиль пары (дни вместе, общие факты, ответы на вопросы), настройки |
| **Настройки** | Имя и «он/она», тема, приглашение; парные (меняются только по согласию обоих); личные (цикл, выгрузка данных в JSON); уведомления на устройстве |
| **Вход** | Google или ссылка на почту → создать пространство или войти по коду/ссылке → знакомство и 8 вопросов (любой можно пропустить) |

## Запуск за 15 минут

### 1. База (Supabase → SQL Editor)

Выполните по очереди, каждый файл целиком:

1. `supabase/migrations/0001_bepair_redesign.sql`
2. `supabase/migrations/0002_bepair_complete.sql`
3. `supabase/migrations/0003_bepair_native.sql`
4. `supabase/migrations/0004_bepair_reminders.sql`
5. `supabase/migrations/0005_bepair_partner_profile.sql`
6. `supabase/migrations/0006_bepair_dates_moon.sql`
7. `supabase/migrations/0007_bepair_planerka.sql` — планёрка: колесо баланса, вопросы, дела, расписание
8. `supabase/migrations/0008_bepair_planerka_comments.sql` — комментарии к оценкам колеса
9. `supabase/migrations/0009_bepair_letters_type_default.sql` — письма снова отправляются (старая колонка `type`)
10. `supabase/migrations/0010_bepair_planerka_close.sql` — каждый закрывает свою часть планёрки
11. `supabase/migrations/0011_bepair_album.sql` — общий альбом для фото-виджета
12. `supabase/migrations/0012_bepair_lang.sql` — язык каждого (русский / английский) для уведомлений
13. `supabase/migrations/0013_bepair_reset_space.sql` — удаление всех данных пары по согласию обоих
14. `supabase/migrations/0014_bepair_todo_week.sql` — дела планёрки на неделю: перенос дела с прошлой недели
15. `supabase/migrations/0015_bepair_courses.sql` — курсы, журнал саморефлексии, напоминания о курсе
16. `supabase/migrations/0016_bepair_course_rewards.sql` — баллы, значки и серия за курсы; трата баллов на услуги
17. `supabase/migrations/0017_bepair_task_points.sql` — баллы за просьбу начисляет база, ровно один раз; старый триггер `on_checklist_item_completed` и `award_points` удалены
18. `supabase/migrations/0018_bepair_location.sql` — «Где мы»: последняя точка каждого и правило взаимности для карты
19. `supabase/migrations/0019_bepair_battery.sql` — заряд телефона партнёра: едет вместе с точкой «Где мы», под тем же правилом

Все миграции можно запускать повторно — они идемпотентны. `supabase_migration.sql` в корне — старая разовая правка, повторно её не запускайте.

Желательно, но не обязательно: **Database → Extensions → pg_cron** — включить и ещё раз выполнить 0002 и 0004. Тогда отложенные письма доставляются ровно в срок, а не при следующем открытии приложения, и работают напоминания утром и вечером.

### Напоминания утром и вечером

Утром — «вчерашний день партнёра ждёт вас», если он отмечен, открыт вам и вы его ещё не смотрели. Вечером — «можно отметить, как прошёл день», если сегодня не отмечено. Время каждый выбирает сам (по умолчанию 9:00 и 21:30, по местному времени), оба можно выключить.

1. **Database → Extensions**: включить **pg_cron** и **pg_net**, затем ещё раз выполнить `0004_bepair_reminders.sql`.
2. Придумать длинную случайную строку — секрет. В SQL Editor:
   ```sql
   insert into public.bp_server_config (key, value) values
     ('app_url', 'https://vpare.vercel.app'),
     ('cron_secret', 'ваш-секрет')
   on conflict (key) do update set value = excluded.value;
   ```
3. В Vercel добавить переменную `CRON_SECRET` с тем же секретом.

Напоминание о курсе работает так же: каждый включает его сам на странице курса или в «Уведомлениях», выбирает время и дни недели. Приходит, только если курс начат, не закончен и сегодня вы им ещё не занимались. После 0015 ничего дополнительно настраивать не нужно — его ставит в очередь тот же `bp_reminders_tick`.

Без шага 1 напоминаний нет. Без шагов 2–3 они появляются в ленте приложения, но не приходят push-уведомлением.

### 2. Вход

**Authentication → URL Configuration**

- Site URL: адрес на Vercel, например `https://vpare.vercel.app`
- Redirect URLs: `https://vpare.vercel.app/auth/callback` и `http://localhost:3000/auth/callback`

**Authentication → Providers → Google** (если нужен вход через Google): включить, вставить Client ID и Secret из Google Cloud Console (OAuth client, тип Web). В Google в «Authorized redirect URIs» добавить `https://<ваш-проект>.supabase.co/auth/v1/callback`.

### 3. Push-уведомления

```bash
npx web-push generate-vapid-keys
```

Публичный ключ → `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, приватный → `VAPID_PRIVATE_KEY`. Ещё нужен `SUPABASE_SERVICE_ROLE_KEY` (Project Settings → API) — только на сервере, он отправляет push партнёру. Без этих ключей всё работает, кроме системных уведомлений: лента внутри приложения обновляется сама.

На iPhone push работает только у приложения, добавленного на экран «Домой» (Safari → «Поделиться» → «На экран Домой»), iOS 16.4+.

### 4. Локально

```bash
cp .env.example .env.local   # заполнить
npm install
npm run dev
```

### 5. Vercel

Import репозитория → Framework: Next.js → Environment Variables: все переменные из `.env.example` → Deploy. После первого деплоя вернитесь к шагу 2 и проверьте адреса.

## Приложения для iPhone и Android с виджетами

Виджеты на экране «Домой» системы дают только нативным приложениям — сайту и PWA нельзя. Поэтому рядом с веб-версией есть нативная оболочка на Capacitor 8 (`android/`, `ios/`). Внутри — то же веб-приложение с вашего Vercel, плюс то, что умеет только натив: виджеты и нативные push.

| Виджет | Где | Что показывает |
|---|---|---|
| **День** | iPhone и Android, маленький | Двое персонажей-кружков играют ваш день и день партнёра (не отмечен, лёгкий, обычный, тяжёлый, закрыт), одна фраза о сегодняшнем дне |
| **Пара** | iPhone и Android, средний | То же + дни вместе, серия, ждущие письма и просьбы, кнопки «Отметить» и «Весточка» |
| **День** | экран блокировки iPhone | Одна-две строки или одна строка над часами |
| **Серия** | экран блокировки iPhone | Число дней подряд в круге |
| **Карта** | Android, 4×2 (растягивается) | Вы и партнёр на карте, расстояние, когда обновлялось и заряд телефона партнёра. Только когда вы оба включили «Где мы» |

**Экран блокировки (Android):** тихое постоянное уведомление «Статус дня» с той же фразой, что на виджете. Включается в Профиль → Виджеты, без звука и вибрации, обновляется вместе с виджетами.

Правило «сначала свой день» действует и тут: пока вы не отметили свой, у партнёра на виджете видно только «отмечено» и замочек — без цвета и слова. В настройках → «Виджеты» можно скрыть настроение совсем (для экрана, который видят другие) и отключить потерянный телефон.

Как это работает: при первом входе в нативном приложении оно получает свой ключ виджета (только чтение, хранится хэшем в `widget_tokens`). Виджет раз в 15–30 минут спрашивает `/api/widget` и обновляется сразу, когда вы что-то делаете в приложении.

### Что нужно один раз

1. Выполнить миграцию `supabase/migrations/0003_bepair_native.sql`.
2. В Supabase → Authentication → URL Configuration добавить в Redirect URLs адрес `vpare://auth-callback`: в приложении вход через Google и по ссылке возвращается сюда.
3. В GitHub → Settings → Secrets and variables → Actions → **Variables** создать `BEPAIR_URL` со значением адреса на Vercel (например `https://vpare.vercel.app`).

### Android

Сборка идёт сама при каждом мёрдже в `main` и выкладывается по постоянной ссылке: https://github.com/raduntsev/bepair/releases/download/android-latest/vpare.apk (в приложении: Профиль → «Приложение на телефон» → «Скачать для Android»). Тот же APK лежит в Actions → «Native apps» → артефакт **vpare-android-debug**.

Чтобы новая версия ставилась поверх старой (без удаления и повторного входа), сборки должны подписываться одним ключом. Один раз создайте ключ: `keytool -genkeypair -v -keystore vpare.keystore -alias vpare -keyalg RSA -keysize 2048 -validity 10000`, затем в GitHub → Settings → Secrets and variables → Actions добавьте секреты `ANDROID_KEYSTORE_BASE64` (результат `base64 -w0 vpare.keystore`) и `ANDROID_KEYSTORE_PASSWORD`. Без них каждая сборка подписана временным ключом. Установить на телефон: скачать, открыть, разрешить установку из этого источника. Затем долгое нажатие на рабочем столе → «Виджеты» → Впаре.

Собрать локально: Android Studio → Open → папка `android` (перед этим `BEPAIR_URL=https://… npx cap sync android`).

Push на Android: Firebase-проект `vpare-3235a`, его `google-services.json` лежит в `android/app/` (это не секрет — настройки клиента). Без этого файла приложение не регистрируется в FCM (иначе Android закрыл бы его) и пишет, что push в этой сборке не подключён. Для сервера: Firebase → Project settings → Service accounts → Generate new private key, содержимое JSON положить в переменную Vercel `FCM_SERVICE_ACCOUNT`.

### iPhone

Нужны Mac с Xcode 16+ и платный Apple Developer Program: App Groups, через которые виджет получает данные, бесплатному аккаунту недоступны.

1. `npm install && BEPAIR_URL=https://… npx cap sync ios`
2. Открыть `ios/App/App.xcodeproj`.
3. В целях **App** и **VpareWidget** → Signing & Capabilities выбрать свою команду. Если Xcode попросит, подтвердить App Group `group.app.bepair.vpare` и Push Notifications.
4. Подключить iPhone, выбрать схему **App** → Run.
5. Виджет: долгое нажатие на экране «Домой» → «Изменить» → «Добавить виджет» → Впаре.

Push на iPhone: Apple Developer → Keys → новый ключ с APNs. Переменные Vercel: `APNS_KEY` (содержимое .p8), `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_BUNDLE_ID=app.bepair.vpare`; `APNS_PRODUCTION=1` для сборок из TestFlight и App Store.

Компиляцию iOS проверяет та же сборка GitHub Actions: она собирает приложение и расширение для симулятора без подписи.

## «Где мы»: карта на двоих

Правило то же, что у дня: точку партнёра видно, только пока делитесь и вы. Каждый включает сам на экране «Где мы» (Профиль → «Где мы»); партнёр получает уведомление «Аня начала делиться местоположением» — факт, без места. Выключить может любой в любую секунду: его точка удаляется сразу, и карта закрывается для обоих. Правило живёт в SQL (`0018`): чужие точки не приходят в браузер, а не прячутся интерфейсом.

Хранится только последняя точка каждого — одна строка в `locations`, без истории перемещений. Выход из пары или удаление данных пары стирают её и выключают показ.

Как часто обновляется:

- **Android-приложение** — каждые 5 минут, даже когда оно закрыто. Это постоянный сервис с тихим уведомлением «Вы делитесь местоположением» и кнопкой «Не делиться» (она выключает показ для аккаунта, а не только для телефона). Фоновым задачам Android разрешает просыпаться не чаще раза в 15 минут, поэтому без сервиса 5 минут не получить. Местоположение берётся по Wi-Fi и сотовым вышкам, без постоянного GPS. Если разрешить доступ «Всегда», сервис сам включается после перезагрузки телефона.
- **Браузер и iPhone** — пока Впаре открыта: точка уходит при открытии и раз в 5 минут.

Карта — тайлы OpenStreetMap без ключа, приглушённые до серого (в тёмной теме — инвертированные), чтобы цветными оставались только две точки. Подпись «© OpenStreetMap» обязательна и есть и на карте, и на виджете. Виджет кэширует тайлы на 30 дней и не скачивает карту заново, пока точки не сдвинулись. Правила OSM допускают такое лёгкое использование; если пар станет много, стоит перейти на платного поставщика тайлов (MapTiler, Stadia) — адрес задан в `src/lib/location.ts` и `MapTiles.java`.

### Заряд телефона партнёра

Вместе с точкой телефон отправляет свой заряд — те же раз в 5 минут, то же правило: видно, только пока вы оба делитесь местоположением. Процент стоит маленькой плашкой у аватара партнёра (Профиль → «Вы и …» и экран пары) и в заголовке виджета «Карта»: «Аня · 84 %», с ⚡ во время зарядки; при 15 % и ниже плашка красная. Если точке больше часа, заряд не показывается — он уже ничего не говорит о телефоне сейчас. Хранится одно последнее значение, без истории.

Откуда берётся заряд: Android-приложение — из системы, вместе с каждой точкой; Chrome и другие браузеры на Chromium — через Battery API, пока Впаре открыта. Safari, Firefox и iPhone свой заряд сайтам не сообщают — у таких партнёров процента не будет.

После обновления APK с «Картой» Android один раз спросит разрешение на местоположение — когда вы включите «Где мы».

## Как устроена взаимность

Правило «сначала свой день» живёт в SQL, а не в интерфейсе: пока вы не отметили день, строки партнёра за эту дату и закрытые письма просто не приходят в браузер. Там, где нужно показать факт без содержания (отметка в календаре, «письмо ждёт вас»), работают функции, возвращающие только присутствие. Уведомления тоже сообщают факт («Аня отметила день»), а не содержание.

«Сегодня» считается в часовом поясе человека: приложение сообщает его базе при каждом входе.

## Проверено (нативные приложения)

Android: APK собирается; виджеты прогнаны через Robolectric с настоящим рендерингом — все состояния в светлой и тёмной теме, превью сохраняются в `android/app/build/widget-previews`. Тест поймал падение «нельзя использовать View в RemoteViews» до того, как оно попало на телефон. `/api/widget` проверен на локальной базе: пока свой день не отмечен, цвет партнёра в ответе отсутствует. Подписи APNs (ES256) и FCM (RS256) проверены на одноразовых ключах.

iOS: компилируется в GitHub Actions на macOS. На живом iPhone не запускалось.

## Проверено

Миграции прогнаны на чистом Postgres 16 дважды подряд; сценарии RLS проверены от лица двух пользователей. `0017` прогнана дважды на копии боевой схемы вокруг просьб (со старым триггером): сначала воспроизведена ошибка — отказ RLS в приложении, двойная оплата при повторе, падение виджета на «Recipient not in same space», — затем после миграции из приложения, из виджета, при двойном нажатии и повторе после отката у каждой просьбы ровно одна строка `task` в `points_ledger`, баллы получает тот, кого просили. Приложение прогнано через настоящий PostgREST поверх этой базы в Playwright: отметка дня с раскрытием партнёра, задачи, письма, весточка со снимком, создание пространства, онбординг, вход по ссылке-приглашению, согласование парной настройки.

Не проверялось вживую (нужен настоящий проект Supabase): вход через Google, отправка писем со ссылкой, загрузка файлов в Storage, Realtime и доставка push на телефон.
